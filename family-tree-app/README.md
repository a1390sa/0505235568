# شجرة العائلة (Family Tree App)

تطبيق ويب خاص لأرشفة شجرة عائلتك: أنشئ الشجرة، شارك رابط الدعوة مع أفراد
عائلتك (بدون كلمات مرور)، وأضيفوا/عدّلوا الأفراد والعلاقات معاً على مخطط
نسب (pedigree) تفاعلي.

## المزايا

- **بدون كلمة مرور**: كل من يملك رابط الدعوة يدخل باسمه فقط، وله نفس
  صلاحيات الإضافة/التعديل/الحذف.
- **مخطط نسب تفاعلي**: تكبير/تصغير وسحب، مع بحث بالاسم يقفز للعنصر ويوسّطه.
- **علاقات مرنة**: كل رابط أب/أم مستقل عن الآخر، وكل شخص يمكن أن يكون له
  أكثر من زواج (طلاق/زواج ثانٍ) دون التأثير على أبنائه من الزواج الآخر.
- **عربي بالكامل (RTL)**.
- صورة، تاريخ ميلاد/وفاة، وملاحظات لكل فرد.

## التقنية

Next.js 16 (App Router) + TypeScript + Tailwind + Prisma + PostgreSQL.
تم اختيار هذا التكديس لأنه يُنشر بسهولة على Vercel بضغطة واحدة (الاستضافة
المُوصى بها)، ولأن قاعدة بيانات علائقية (PostgreSQL) تمثّل روابط القرابة
بدقة أكبر من قاعدة بيانات مستندية.

## التشغيل محلياً

يحتاج المشروع قاعدة بيانات PostgreSQL محلية (أو أي Postgres تصل إليه).

```bash
# 1) ثبّت الحزم
npm install

# 2) اضبط رابط الاتصال بقاعدة البيانات في .env
cp .env.example .env   # ثم عدّل DATABASE_URL

# 3) طبّق المخطط (schema) على القاعدة
npx prisma migrate dev

# 4) شغّل خادم التطوير
npm run dev
```

افتح http://localhost:3000

## النشر على الإنتاج (Vercel + Neon Postgres)

هذا هو المسار الموصى به لأنه لا يحتاج أي إعداد خوادم:

1. أنشئ قاعدة بيانات Postgres مجانية على [Neon](https://neon.tech) أو
   [Vercel Postgres](https://vercel.com/storage/postgres) وانسخ رابط الاتصال.
2. ادفع هذا المجلد إلى مستودع GitHub، ثم استورده في [Vercel](https://vercel.com/new).
3. في إعدادات المشروع على Vercel، أضف متغير البيئة `DATABASE_URL` برابط
   قاعدة البيانات من الخطوة 1.
4. عند أول نشر، شغّل `npx prisma migrate deploy` (يمكن ربطه كخطوة Build
   Command، مثلاً: `prisma migrate deploy && next build`).

لا حاجة لتغيير أي شيء في `prisma/schema.prisma` — نفس مخطط PostgreSQL
يُستخدم محلياً وفي الإنتاج.

## بنية المشروع

```
src/
  app/
    page.tsx            # الصفحة الرئيسية (إنشاء عائلة)
    join/[token]/        # صفحة الانضمام برابط الدعوة
    tree/                # صفحة الشجرة (تتطلب جلسة)
    api/                 # نقاط CRUD للأفراد والعلاقات
    actions/family.ts    # Server Actions: إنشاء عائلة / انضمام / خروج
  components/tree/        # شاشة الشجرة: اللوحة، البطاقات، النماذج
  lib/
    layout.ts            # خوارزمية ترتيب الشجرة (أجيال + أزواج)
    auth.ts               # جلسات الدعوة (كوكي + جدول Session)
    db.ts                 # عميل Prisma
prisma/schema.prisma       # نموذج البيانات (Family, Person, Union, ParentChild...)
```

## قرارات تصميم يستحسن معرفتها

- **لا يوجد نظام صلاحيات متدرّج عمداً**: كل الأفراد المدعوين متساوون
  (بناءً على طلب صاحب المشروع)، فأي شخص يملك رابط الدعوة يمكنه حذف بيانات.
  شارك الرابط فقط مع من تثق بهم، ولا تنشره علناً.
- **الصور** تُخزَّن كـ base64 داخل قاعدة البيانات مباشرة (مع تصغير من
  جهة المتصفح قبل الرفع) لتفادي الاعتماد على تخزين ملفات خارجي — مناسب
  لحجم عائلة عادي (عشرات إلى مئات الأفراد)، ويمكن تحويله لاحقاً لتخزين
  سحابي (S3 مثلاً) إذا كبر الأرشيف كثيراً.
- **بدون استيراد/تصدير GEDCOM حالياً** (لم يكن مطلوباً)، لكن نموذج
  البيانات (Person/Union/ParentChild) قابل للتوسعة له لاحقاً.
